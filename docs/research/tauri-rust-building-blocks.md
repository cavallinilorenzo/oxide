# Oxide MVP: Tauri v2 and Rust building blocks

**Scope:** macOS-first desktop MVP; recommendation based on Oxide's checked-out domain model (`Project` = local Git repository; terminal and diff are `Surface`s) and current official documentation/API sources. Links were checked 2026-10-21. Recommendations below are inferences from the documented capabilities, not benchmark results.

## Decisions

| Area | MVP choice | Tradeoff / boundary |
|---|---|---|
| Rust ↔ webview IPC | Tauri commands for request/response and lifecycle controls; a Tauri `Channel` per PTY for ordered stdout/stderr chunks and structured terminal lifecycle/exit messages; events for low-rate app-wide notifications only. | Tauri explicitly recommends channels for ordered high-throughput data; events are JSON payloads and evaluated as JavaScript, and are unsuitable for large payloads. No documented bytes/sec, message-size, or latency ceiling was found, so benchmark realistic terminal workloads and batch output (avoid one IPC message per byte). [Calling frontend](https://v2.tauri.app/develop/calling-frontend/) [Calling Rust](https://v2.tauri.app/develop/calling-rust/) |
| PTY / terminal | `portable-pty` in Rust, `@xterm/xterm` in webview, with `@xterm/addon-fit`; spawn the selected interactive shell with a PTY, propagate input, resize, output, and exit status. | `portable-pty` provides a runtime-selectable cross-platform PTY API, master reader/writer, and child process handle. xterm.js is a terminal emulator, not a shell/PTY; it supports terminal apps and offers optional WebGL rendering. GPU renderer/context availability and real-world throughput on Tauri's WKWebView are not guaranteed by these sources; retain DOM fallback and measure. [portable-pty](https://docs.rs/portable-pty/latest/portable_pty/) [xterm.js](https://github.com/xtermjs/xterm.js) |
| Local Git | Use installed `git` CLI for mutating and compatibility-sensitive operations (commit, fetch/push, worktree add/list/remove, rebase/merge); call with argument arrays, explicit cwd, and no shell interpolation. Use `git status --porcelain=v2 -z` for stable parsing, or adopt `git2` for local status/diff if API ergonomics justify it. | CLI best matches user's Git config, hooks, credential helpers, and Git behavior; downside is dependency on an installed compatible executable and parsing/process management. `git2` is actively documented, reads/writes repos, and exposes status/diff/worktree APIs, but is a libgit2 binding and not identical to every Git CLI feature/configuration. `gitoxide` (`gix`) is a pure-Rust library with fast/correctness goals, but its own project status docs should be checked per feature before relying on it for all push/worktree operations. Defer it for MVP. [git status](https://git-scm.com/docs/git-status) [git worktree](https://git-scm.com/docs/git-worktree) [git2](https://docs.rs/git2/latest/git2/) [gitoxide](https://github.com/GitoxideLabs/gitoxide) |
| GitHub | Use `gh` CLI for MVP GitHub operations and `gh api` for endpoints not covered by a command. `gh api` supports REST and GraphQL and uses gh's authenticated request path. Reuse auth only via a narrowly scoped backend call to `gh auth token`; do not read or copy gh's credential files. | `gh` avoids implementing login, account switching, host selection, and token storage. Its manual documents token output, so any reuse transfers a bearer secret into Oxide's process; keep it in Rust memory only, never frontend state/logs/storage. If a first-class in-app GitHub experience later needs typed APIs, use `octocrab` with an explicit OAuth/device flow or app auth; it does not automatically inherit gh auth. [gh auth token](https://cli.github.com/manual/gh_auth_token) [gh api](https://cli.github.com/manual/gh_api) [octocrab](https://docs.rs/octocrab/latest/octocrab/) |
| Close window / keep alive | Intercept Tauri close request, prevent destruction, hide the window; expose reopen via Dock/menu-bar/tray affordance. Keep app event loop alive until explicit Quit. | AppKit specifies that the app may remain active after its last window closes when the delegate returns `false`. Tauri's window API exposes close-request events and prevention; exact app-wide lifecycle wiring should be validated on macOS because the AppKit behavior is native-platform fact, while mapping it to a Tauri lifecycle hook is an implementation inference. A hidden app needs a clear reopen and quit path. [Tauri window events](https://v2.tauri.app/reference/javascript/api/namespacewindow/) [Apple AppKit](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminateafterlastwindowclosed%28_%3A%29) |
| Repository discovery | Start from user-selected roots; use `ignore::WalkBuilder`/`build_parallel()` to search for `.git` directories and `.git` files (linked worktrees), pruning `.git` internals and respecting symlink boundaries. Cache discovered roots and refresh incrementally with filesystem notifications, plus an explicit rescan. | The `ignore` crate is designed as a fast recursive walker and parallelizes, respects ignore rules, and can prune directories. That supports fast broad scans but does not itself identify every repository/worktree topology; detection and handling nested repos, bare repos, permissions, network volumes, and aliases are Oxide logic. Never recursively traverse a repo's `.git` object database just to discover projects. [ignore crate](https://docs.rs/ignore/latest/ignore/) [WalkBuilder](https://docs.rs/ignore/latest/ignore/struct.WalkBuilder.html) |

## Verified facts vs inference and unknowns

**Verified:** Tauri commands are request/response; channels are documented for fast ordered streams and used internally for streaming operations; events have looser typing and are not suitable for large payloads. `portable-pty` exposes cross-platform PTY traits and native system selection. xterm.js consumes PTY input/output but does not provide a shell. `git status --porcelain` is intended for stable script parsing; Git provides porcelain worktree listing. gh can print the active host/account token and `gh api` can call REST or GraphQL. `ignore::WalkBuilder` supports parallel traversal and standard ignore rules. Apple AppKit documents remaining active after the last window closes.

**Inference:** These facts make Channels + portable-pty + xterm.js, CLI-backed mutating Git, gh-backed GitHub MVP, and `ignore`-based discovery the lowest-risk initial combination for Oxide. Exact performance depends on chunk size, workload, repo scale, filesystem, WebKit version, installed tools, and user Git setup; benchmark before setting UX thresholds.

**Unknowns to settle during implementation:** Tauri Channels' practical terminal throughput/queueing/backpressure behavior; WebGL renderer reliability in shipped WKWebView versions; desired behavior when Git/gh are absent or old; exact Git CLI behavior under custom aliases/hooks/credential helpers; whether background PTYs must survive macOS App Nap or system sleep; discovery roots, depth and network-volume policy. Keep PTY ownership in Rust app state (not the webview) so hiding/recreating a window need not implicitly terminate the child, then verify shutdown semantics.
